# דשבורד קמפיינים - מאורה (Google Sheets)

`maora-dashboard.gs` בונה לשונית **"דשבורד"** מעוצבת מתוך שני מקורות:

| מקור | מה נלקח ממנו |
|---|---|
| **מאורה טבלה מעודכנת** | תאריך יצירה (חודש), מקור הליד / אופן הגעה (= שם קמפיין), סטטוס תהליך (`מכירה` = מכירה), פרמיה חודשית, מילת מפתח, נציג מכירות |
| **גיליון העלויות** | תאריך / תקופה, שם קמפיין, עלות קמפיין (ואופציונלית מילת מפתח) |

העמודות מזוהות **לפי שם הכותרת**, לא לפי אות העמודה, כך שהוספת עמודות לא שוברת כלום.

## מה יש בדשבורד

- **מסננים**: מחודש / עד חודש / קמפיין (רשימות נפתחות). שינוי מסנן מרענן את הדשבורד.
- **10 כרטיסי KPI**: לידים, מכירות, אחוז סגירה, סה"כ פרמיה חודשית, פרמיה ממוצעת, עלות קמפיינים, עלות לליד, עלות לסגירה, עלות פרמיה, קמפיינים פעילים.
- **טבלת ביצועים לפי קמפיין** עם שורת סה"כ, באותן הגדרות כמו הדוח הידני הקיים:
  - אחוז סגירה = מכירות ÷ לידים
  - פרמיה ממוצעת = סה"כ פרמיה ÷ מכירות
  - עלות לליד = עלות ÷ לידים, עלות לסגירה = עלות ÷ מכירות
  - עלות פרמיה = עלות ÷ סה"כ פרמיה
- **מגמה חודשית**, **מילות מפתח מובילות**, **נציגי מכירות**.
- **4 גרפים**: לידים ומכירות לפי חודש, פרמיה מול עלות לפי חודש, חלוקת לידים לפי קמפיין, פרמיה לפי קמפיין.
- אין `#DIV/0!` / `#VALUE!` - כשאין נתון מוצג `—`.

## התקנה (5 דקות)

1. צור **קובץ Google Sheets חדש** לדשבורד (מומלץ קובץ נפרד: הוא מכיל רק סיכומים, בלי שמות ות"ז, ולכן בטוח לשיתוף עם הלקוח).
2. בקובץ: **הרחבות → Apps Script**. מחק את התוכן והדבק את כל `maora-dashboard.gs`.
3. מלא בראש הקובץ את `CONFIG`:
   - `LEADS_SPREADSHEET_ID` - ה-ID של "מאורה טבלה מעודכנת" (החלק שבין `/d/` ל-`/edit` בכתובת).
   - `LEADS_SHEET_NAME` - שם הלשונית (ריק = הראשונה).
   - `COSTS_SPREADSHEET_ID` / `COSTS_SHEET_NAME` - אותו דבר לגיליון העלויות.
   - אם יש סטטוסים נוספים שנחשבים מכירה - הוסף ל-`SALE_STATUSES`.
4. שמור, רענן את הגיליון, ובתפריט **📊 דשבורד → התקנה (פעם אחת)**. אשר את ההרשאות.
   זה בונה את הדשבורד, מרענן אותו כל שעה, ומרענן מיידית כשמשנים מסנן.
5. שתף את קובץ הדשבורד עם הלקוח כ**צופה**.

## גיליון העלויות - פורמטים נתמכים

- טבלה שטוחה: `תאריך | שם קמפיין | עלות קמפיין` - שורה לכל חודש/קמפיין.
- הדוח הידני הקיים (בלוקים עם שורות כותרת ושורות סה"כ חוזרות) - שורות בלי עלות מספרית ושורות `סה"כ` מדולגות אוטומטית.
- תאריך יכול להיות `07/2025`, תאריך מלא, או תקופה כמו `1-28/08/2025`.
- **תקופות מצטברות**: אם לאותו חודש וקמפיין יש `1-6/08/2025` וגם `1-28/08/2025`, נלקחת רק המאוחרת (אחרת העלות נספרת פעמיים). תקופות שלא מתחילות באותו יום (`1-7`, `8-14`...) נסכמות.
- שמות קמפיינים מותאמים בין הגיליונות גם אם יש הבדלי רווחים/סוגריים (`( כספים אבודים )` = `(כספים אבודים)`). קמפיין שכתוב אחרת לגמרי יופיע כשתי שורות - כדאי לאחד את השם במקור.

## גרסת אתר (`maora-dashboard.html`)

דף אחד שנפתח תוך שנייה, בלי לחכות ל-Apps Script:

- בכל רענון הסקריפט כותב גם לשונית **"נתונים לאתר"** - סיכום קטן לפי חודש,
  קמפיין, מילת מפתח ונציג (בלי שמות לקוחות או ת"ז).
- הדף טוען רק את הסיכום הזה כ-CSV ומחשב הכל בדפדפן, כך ששינוי מסנן מיידי.
- בביקור חוזר מוצגים מיד הנתונים מהביקור הקודם, ומתחלפים כשהטריים מגיעים.

### חיבור

האתר קורא את הנתונים דרך הסקריפט עצמו (אפליקציית אינטרנט), לא דרך "פרסום
באינטרנט" - Google חוסמת לפעמים קריאה של CSV מפורסם מאתר אחר.

1. ב-Apps Script: **פריסה ← פריסה חדשה** ← סוג **אפליקציית אינטרנט** ←
   הפעלה בתור **אני** ← למי יש גישה **כל אחד** ← פריסה. מאשרים הרשאות.
2. בקובץ הדשבורד: **📊 דשבורד ← קישור לאתר** ומעתיקים את הקישור. הוא כולל
   מפתח אקראי; בלעדיו הסקריפט מחזיר רק `forbidden`.
3. פותחים את `maora-dashboard.html` בדפדפן (כש-`ENCRYPTED_SOURCE` ריק),
   מדביקים את הקישור, בוחרים שם משתמש וסיסמה, ולוחצים "צור קוד". את הקוד
   מדביקים בין הגרשיים של `ENCRYPTED_SOURCE`.
4. משנים את שם הקובץ ל-`index.html`, שמים אותו בתיקייה וגוררים את התיקייה ל-
   https://app.netlify.com/drop.

אחרי שינוי קוד בסקריפט: **פריסה ← ניהול פריסות ← עריכה ← גרסה: גרסה חדשה**,
אחרת האפליקציה ממשיכה להריץ את הקוד הישן. הקישור לא משתנה.

### סיסמה

הקישור לנתונים נשמר בקובץ רק מוצפן (AES-GCM, מפתח שנגזר ב-PBKDF2 משם המשתמש
והסיסמה). הסיסמה עצמה לא נמצאת בקובץ, ובלעדיה אי אפשר לדעת מהקוד מאיפה
הנתונים מגיעים. החלפת סיסמה = מרוקנים את `ENCRYPTED_SOURCE`, יוצרים קוד חדש
ומעלים שוב.

המגבלה: מי שמשיג את קישור הנתונים עצמו (למשל משתמש מחובר שמעתיק אותו מכלי
המפתחים) יכול לקרוא את הסיכום בלי סיסמה - אותם נתונים שהוא רואה ממילא, בלי
פרטים אישיים. כדי לבטל גישה: מבטלים את הפרסום ומפרסמים מחדש (נוצר קישור חדש),
ויוצרים קוד חדש. (כדי לבטל קישור: מוחקים את SITE_KEY במאפייני הסקריפט -
הגדרות הפרויקט ← מאפייני סקריפט - ונוצר מפתח חדש.)
