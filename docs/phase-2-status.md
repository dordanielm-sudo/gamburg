# מצב הפרויקט: שלב 1, התוספות, ושלב 2

מסמך תמונת-מצב אחד: מה כלל שלב 1, מה נבנה מעבר לו, ומה מתוך שלב 2 כבר
קיים. המקור לשלב 1 הוא הצעת המחיר החתומה; המקור לשלב 2 הוא גיליון
הדרישות של הלקוחה.

---

## שלב 1 — ההצעה החתומה

**נתונים:** רשימה סגורה של שדות ברמת התיק — מספר תיק, שם, תאריך פתיחה,
סוג, מהות, מטפל, זיהוי נוסף, פרטי לקוח (ת.ז, טלפון, בן זוג), סטטוס, צוות.

**מודולים:** דשבורד מנהלים; לשונית משימות + התראות In-App; ניהול תיקים
פתוחים (טבלה עם מיון וחיפוש); מלל מנהל + תיבת מעקב; סימוני לקוח בעייתי/
לא משלם/מעביר מסמכים; זיהוי תיק שלא נגעו בו מעל חודש; הזנה דו-צדדית —
webhook ל-Make על **עדכון סטטוס או סימון ידני**.

**מסחרי:** 10,500 ₪ + מע"מ, 3-4 שבועות, 30 ימי אחריות.

---

## מה נבנה מעבר לשלב 1

הפירוט המלא ב-`docs/scope-additions.md` (35 פריטים ממוספרים). בתמצית:

| קבוצה | מה |
|---|---|
| **מודולים שלמים שאינם בהצעה** | חוצצים, מועדים, בקרה ואישורים, מסמכים, שלבים בתיק |
| **הרחבות** | סינון מתקדם + תבניות שמורות, גרירת עמודות, עמודות לפי סוג תיק, מסך ניהול משתמשים, מסך וובהוקים, עימוד, דחיפות ומיון |
| **תשתית סנכרון** | חמישה scenarios במקום אחד, Data Store כ-checkpoint, התאמת משימות, תיקון backfill |
| **עריכה דו-כיוונית** | ההצעה מתמחרת שני טריגרים; נבנה מנגנון עריכה גנרי לכל שדה, חמישה סוגי ישויות, עם ניתוב וזיהוי מקור לכל אחד |
| **כתיבה חזרה בפועל** | הנדסה לאחור של סכימת עדכנית — ה-view של החוצצים אינו ניתן לכתיבה, ונדרשה כתיבה ישירה לשש טבלאות |
| **יצירת משימות** | פתיחת משימה חדשה בעדכנית (`Tasks` + `TaskUsers`), כולל מיפוי משתמשים |
| **ביצועים** | טעינת מסך ירדה מ-~7.7 שניות |

**חשוב מסחרית:** חלק מהתוספות האלה הן בפועל **דרישות של שלב 2** שכבר
סופקו — במיוחד יצירת משימות דרך האפליקציה, שלבים ותתי-שלבים, המועדים,
והסינון המתקדם. הן מסומנות ככאלה בטבלה למטה.

## שלב 2 — מצב ביצוע

### נבנה ✅

| דרישה | הערה |
|---|---|
| הוספת משימה דרך האפליקציה | כולל יצירה בפועל בעדכנית |
| עדכון משימה בחוצץ בעדכנית | הכתיבה חזרה |
| הרשאות עובד "למזל בלבד" | עובד מעצם ה-RLS: מנהל רואה הכל, כל אחד אחר רק מה שהוקצה לו או שיצר |
| חוצץ "לקוח חדש" — ת.ז, ייפוי כוח, הסכם שכ"ט, החרגת רכב, הפעלת עסק, הוראות נוהל, חוב לרשויות, עיכוב הליכים, ייצוג בהוצל"פ, צ'ק פיקדון | מסונכרנים כשדות חוצץ, וגם קיימים כתתי-שלבים תחת "קליטה" |
| טופס 5 — מועד אחרון, דחוף | מודול המועדים |
| דיונים — חקירה, דיון, ישיבת הסדר, אסיפת נושים | מועדים |
| כל התאריכים יחד | מסך המועדים |
| כתובת, זום, קישור לזום, "לקוח מעודכן" | קיים |
| בקרה — סינון לפי החרגת רכב / הפעלת עוסק / תצהיר / הגשת טופס 5 | בונה-התנאים תומך בכל שדה חוצץ |
| בניהול תיקים — סינון לפי כותרת או סנן שהוספנו | אותו מנגנון |

### חלקי ⚠️

| דרישה | מה חסר |
|---|---|
| סינוני משימות: דחוף / חדש / הושלם / לטיפול השבוע / לא טופל עדיין | בונה-התנאים **אינו קיים במסך המשימות** — הוא רק בתיקים, מועדים, אישורים ודשבורד. שם יש בורר סטטוס ומיון בלבד |
| סינון משימות לפי מטפל | אותו פער |
| השלמת מסמכים — תיבת סימון "הושלם / חלקי" | החוצצים קיימים; חישוב ההשלמה המצטבר לא |
| הרשאת עורך דין שיוכל לשנות | שלושה תפקידים (מנהל/מטפל/מזכירה) — אין רמת "עורך דין" נפרדת |

### לא נבנה ❌

**שלושה מודולים שלמים:**

1. **דואר היברידי** — ניהול ומעקב, תאריך שליחה, התראה אם עבר שבוע,
   "נמסר והתקבל אישור סרוק (רשום)"
2. **דוח דו-חודשי ודוח חצי שנתי** — טבלה בסגנון הגיליון (מספר תיק, עו"ד
   מטפל), הערות מנהל, הפרדה שולה / שאר הצוות, הזרימה מוכן → נשלח לחתימה
   → לקוח חתם → הוגש, ובדוח החצי שנתי גם השוואת הפרשים מול נתוני טופס 5
3. **מחשבון תשלום חודשי** — מחשבון אוטומטי לפי הנתונים הראשוניים, ו"סה"כ
   חוב מקורי נכון להיום"

**פריטים נוספים, כל אחד בפני עצמו:**

- וואטסאפ — תיעוד פניות ("האם בוצעה פנייה", "כמה פניות לתעד") והודעות
  תזכורת אוטומטיות ללקוח
- תיעוד שיחות — "לקוח חייג למשרד" → סימון → המטפל מקבל עדכון
- שליחת מייל ל-CRM שייכנס לעדכנית
- סיכום AI של מה שהלקוח שולח
- חיבור לאאוטלוק
- עדכון לקוח אוטומטי מרגע העדכון, בנוסח קבוע
- שעה למועד (כרגע תאריך בלבד, בלי שעה)
- סיסמא + הגבלה למחשבים שנגדיר
- הרשאה למכירות
- "לא רלוונטי מהחוצץ — לא יופיע בסינונים" (למשל לקוח עבר)
- "כבר לא לקוח חדש ולא יופיע"
- חוצץ "הושלם הכל"

## תמונת המצב בשורה אחת

מתוך כ-40 דרישות בגיליון: **כ-11 נבנו, 4 חלקיות, כ-25 לא התחילו** —
כלומר בערך רבע עד שליש.

מה שנבנה הוא ברובו מה שניתן לגזור מנתוני עדכנית. מה שלא נבנה מתחלק לשניים:
**ערוצים חיצוניים** (דואר רשום, וואטסאפ, מייל, אאוטלוק) ו**לוגיקה עסקית
חדשה** (דוחות, מחשבון). אלה אינם כוונונים של הקיים אלא מודולים בהיקף דומה
למה שכבר נבנה — ובמקרה של הערוצים החיצוניים, גם תלויים בשירותים ובעלויות
שאינם בפרויקט היום.
