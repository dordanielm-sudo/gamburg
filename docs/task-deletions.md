# מחיקת משימות שנמחקו בעדכנית

משימה שנמחקת בעדכנית נמחקת גם ב-CRM. נדרש על ידי הלקוחה.

## למה זה תרחיש נפרד מ-`task-reconcile`

`task-reconcile` שולף את המשימות ה**פתוחות** בעדכנית וסוגר אצלנו כל מה
שנעלם משם. הוא לא יכול להבחין בין משימה שבוצעה למשימה שנמחקה — שתיהן
פשוט מפסיקות להופיע בסריקה — ולכן הוא סוגר ולא מוחק. זו התנהגות נכונה
עבורו ואין לשנות אותה.

ל-`dbo.Tasks` אין עמודת `Deleted` (בשונה מ-`UserData_Defs`/`UserData_Pages`),
כלומר מחיקה שם היא `DELETE` אמיתי. הראיה היחידה למחיקה היא היעדרות מרשימת
**כל** המזהים בטבלה — ולכן התרחיש הזה שולח את כולם, לא רק את הפתוחים.

## השאילתא

מחזירה שורה אחת עם כל המזהים, מופרדים בפסיק — תפעול אחד ב-Make במקום אחד
לכל משימה (~10,000):

```sql
select STRING_AGG(convert(varchar(max), Counter), ',') as source_task_ids
from dbo.Tasks;
```

`varchar(max)` ולא `varchar(20)`: ברירת המחדל של `STRING_AGG` נחתכת ב-8,000
תווים, וכ-10,000 מזהים חורגים מזה בהרבה. חיתוך כזה נראה כמו הצלחה ומוביל
למחיקת כל מה שנחתך.

## המודול ב-Make

HTTP → `POST {CRM}/api/webhooks/task-deletions`, עם ה-header
`x-webhook-secret` (אותו סוד של `task_sync`), וגוף:

```json
{ "source_task_ids": "{{<תוצאת השאילתא>.source_task_ids}}" }
```

הנקודה מקבלת גם מערך וגם מחרוזת מופרדת בפסיקים.

תדירות: פעם ביום מספיקה. זו סריקה מלאה, לא אינקרמנטלית.

## הרצה ראשונה — קודם במצב בדיקה

הריצה הראשונה היא המסוכנת: היא מנקה בבת אחת את כל מה שנמחק בעדכנית מאז
ומעולם, גם מלפני שהתרחיש הזה היה קיים. זה נכון, אבל זה גם בדיוק איך
שנראית שאילתא שבורה — ואין ביטול. לכן קודם:

```json
{ "source_task_ids": "{{...}}", "dry_run": true }
```

התשובה תחזיר `would_delete_here` בלי לגעת בכלום. שתי בדיקות לפני שמורידים
את `dry_run`:

1. `live_in_source` בתשובה צריך להיות שווה ל-`select count(*) from dbo.Tasks`.
   אם הוא קטן ממנו — המחרוזת נחתכה איפשהו, ואסור להריץ.
2. `would_delete_here` צריך להיות מספר שנראה סביר. אם הוא בגודל של כל
   המשימות המסונכרנות — משהו שבור, לא באמת נמחקו כולן.

## דרישה מוקדמת: מיגרציה 0045

`notifications.task_id` הצביע ל-`tasks(id)` בלי `on delete cascade`, כך
שמחיקת משימה שיש עליה התראה נכשלה עם הפרת מפתח זר. מיגרציה 0045 מתקנת
את זה. בלעדיה הריצה תיפול באמצע — חלק מהמנות יימחקו וחלק לא.

## הגנות

- **רשימה ריקה נדחית** (400). אגרגציה שנשברה למעלה הייתה אחרת מוחקת את כל
  המשימות המסונכרנות בבת אחת.
- **משימה ללא `source_task_id` לעולם לא נוגעים בה** — היא נוצרה ב-CRM
  ועדכנית מעולם לא הכירה אותה, אז היעדרותה מהרשימה לא מוכיחה דבר.
- **משימה עם מזהה גבוה מכל מה שברשימה מדולגת.** `Counter` הוא `IDENTITY`
  ולכן רק עולה; משימה שנוצרה מה-CRM אחרי שהצילום נלקח נושאת מזהה גבוה
  מכולם, והיעדרותה ממנו אינה עדות למחיקה. בלי זה היא הייתה נמחקת שניות
  אחרי שנוצרה.

## מה נמחק בפועל

מחיקה מלאה של השורה ב-CRM, כולל שדות שקיימים רק אצלנו (הערות). זו הייתה
הבקשה המפורשת. אם בהמשך יתברר שעדיף לשמר היסטוריה, החלופה היא סימון
המשימה כמבוטלת במקום מחיקתה — שינוי של שורה אחת בנקודה.
