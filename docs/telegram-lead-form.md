# טופס לידים בטלגרם — הקמה ומפרט

טופס השארת פרטים שרץ כ-Telegram Mini App: לקוח פוטנציאלי לוחץ על כפתור בבוט
של המשרד, נפתח לו הטופס בתוך טלגרם, והליד מגיע ל-Make.

- הדף: `/lead` (`app/lead`) — דף ציבורי, בלי חשבון CRM.
- ה-API: `POST /api/telegram-lead` — מאמת מול טלגרם ומעביר ל-Make.

## הזרימה

1. טלגרם פותח את `/lead` בתוך WebView ומזריק את ה-SDK
   (`telegram-web-app.js`) ואת מחרוזת `initData` — מחרוזת חתומה שמזהה את
   המשתמש, חתומה בטוקן של הבוט שלנו.
2. המשתמש ממלא שם וטלפון (השם מגיע מראש משם המשתמש בטלגרם, וניתן לתיקון).
3. הדפדפן שולח `POST /api/telegram-lead` עם `{ name, phone, init_data }`.
4. השרת מאמת את החתימה מול `TELEGRAM_BOT_TOKEN` (`lib/telegram-init-data.ts`),
   מוודא שהמחרוזת לא ישנה מ-24 שעות, ומנרמל את הטלפון.
5. השרת שולח את הליד לוובהוק של Make ומחכה לתשובה סינכרונית — אותו חוזה
   בדיוק כמו הכתיבה חזרה (`lib/make-webhook.ts`).
6. `success` — הטופס נסגר אוטומטית (`tg.close()`). אחרת נשארת הודעת שגיאה
   כללית, והסיבה האמיתית נכתבת ל-`webhook_logs` ולקונסולה.

## הגדרה

### 1. הבוט (BotFather)

1. `/newbot` (או בוט קיים) → שומרים את הטוקן ב-`TELEGRAM_BOT_TOKEN`.
2. `/newapp` → בוחרים את הבוט, ומזינים כ-Web App URL את
   `https://<הדומיין של ה-CRM>/lead`.
3. את הכפתור שפותח את הטופס אפשר להוסיף דרך `/setmenubutton`, או כ-
   `web_app` inline button מתוך הסנריו בטלגרם.

### 2. משתני סביבה

```
TELEGRAM_BOT_TOKEN=123456:ABC...
MAKE_TELEGRAM_LEAD_WEBHOOK_URL=https://hook.eu1.make.com/your-scenario-id
```

בלי `TELEGRAM_BOT_TOKEN` הראוט מחזיר 503 ולא מקבל לידים — אין דרך לדעת
שהפונה הוא באמת משתמש טלגרם, וליד לא מאומת גרוע מכלום.

כתובת הוובהוק נלקחת קודם מ-`webhook_configs` תחת המפתח
`outgoing_telegram_lead` (מסך `/dashboard/webhooks`, לעדכון בלי build מחדש),
ורק אם היא ריקה — ממשתנה הסביבה. אם אין אף אחת מהן, השרת מחזיר `warning`
והליד לא נשלח לשום מקום.

### 3. הסנריו ב-Make

מודול **Custom webhook** שמקבל:

```json
{
  "name":          "שם מלא",
  "phone":         "טלפון מנורמל — ספרות בלבד, עם + אם הוזן",
  "telegram_id":   123456789,
  "username":      "שם משתמש בטלגרם, או null",
  "first_name":    "או null",
  "last_name":     "או null",
  "language_code": "או null",
  "source":        "telegram_lead_form",
  "submitted_at":  "ISO timestamp"
}
```

הסנריו **חייב** להסתיים במודול **Webhook response** שמחזיר:

```json
{ "status": "success" }
```

(`status` יכול להיות גם `failure` או `warning`, עם `message` להסבר.) בלי
מודול כזה Make עונה `Accepted` בטקסט חופשי, וה-CRM סופר תשובה כזאת ככישלון —
בדיוק כמו בכתיבה חזרה.

## אבטחה

- **אימות**: `initData` נחתם על ידי טלגרם ב-HMAC-SHA256 עם הטוקן של הבוט.
  השרת מחשב את אותה חתימה ומשווה בזמן קבוע. בלי הבדיקה הזאת הראוט הוא טופס
  פתוח שכל סקריפט יכול להזרים אליו.
- **תוקף**: `auth_date` ישן מ-24 שעות נדחה, כדי ש-`initData` שנשמר פעם אחת
  לא ישמש לנצח.
- **מה נשמר ביומן**: `webhook_logs` מקבל שם, טלפון ומזהה טלגרם — לא את
  `init_data` עצמו.
- הדף `/lead` פטור מבדיקת ההתחברות ב-`proxy.ts` (matcher), ולכן זהו הדף
  הציבורי היחיד במערכת מלבד `/login`. אין בו שום גישה לנתוני התיקים.

## בדיקה מקומית

`initData` תקין נוצר רק בתוך טלגרם, כך שפתיחת `/lead` בדפדפן רגיל תציג את
הטופס אבל השליחה תיענה ב-401. לבדיקה מקצה לקצה: `ngrok`/דומיין זמני, הזנת
הכתובת ב-BotFather, ופתיחת הבוט מהטלפון.
